# 2025秋计算机体系结构 作业2

## 概述

现代多核计算机系统⼤多在硬件层⾯⽀持共享内存机制。在共享内存系统中，每个处理器内核都能对统⼀的共享地址空间进⾏读写操作。缓存⼀致性协议作为管理各级缓存数据读写权限的重要机制，对保障多核系统中共享缓存的正确运⾏起着关键作⽤。

设计缓存⼀致性协议⾯临严峻挑战，这主要源于协议中存在的多种竞态条件和边界情况。虽然⽬前已开发并验证了若⼲复杂协议，但协议验证作为设计流程中不可或缺却⼜极其困难的环节，仍是学术界持续探索的前沿领域。本次作业要求我们为多核系统设计并验证⼀套缓存⼀致性协议。

我们将采⽤形式化验证⼯具 Murphi 进⾏协议验证。该⼯具通过模型检测技术，在给定系统有限状态模型和期望属性的前提下，⾃动检验这些属性是否在模型所有可达状态中均成⽴。具体⽽⾔，我们需要⽤ Murphi 描述语⾔构建与⼀致性协议对应的有限状态机，并定义⼀组期望属性（即不变式）。Murphi 验证器会系统地枚举所有可达状态空间，检查指定的不变式是否未被违反。

## 实验内容

在本次实验中，你将使⽤形式化验证⼯具 Murphi 实现并验证⼀个基于侦听的 MSI 缓存⼀致性协议。该协议应具备以下特征：

### 基于⼴播的共享总线结构
- 协议通过⼀条共享总线（Bus）实现缓存与内存之间的通信
- 任何读/写请求都会在总线上⼴播，所有缓存同时进⾏监听并响应

### 多缓存系统结构
- 系统包含 3 个缓存（Cache），每个缓存属于不同的处理器
- 每个缓存只包含 1 个⼤⼩为 1 个内存单元的缓存⾏（为简化验证），但能够模拟读写⾏为
- 各缓存通过⼀致性协议保持对同⼀内存块数据的⼀致视图

### 共享主存模块
- 系统中仅包含唯⼀的主存模块，内含 1 个内存单元（为简化验证）
- 当总线上没有缓存响应数据时，由主存向请求⽅提供数据

### 三种缓存状态
- **M（Modified）**：缓存拥有数据的唯⼀有效副本，数据可能与内存不⼀致
- **S（Shared）**：缓存拥有数据的共享副本，数据与内存⼀致
- **I（Invalid）**：缓存⾏⽆效，需从其他缓存或内存获取最新数据

### 处理器⾏为建模
- 处理器可发出读（PrRd）和写（PrWr）请求
- 若请求命中缓存，直接在缓存中读写；若缺失，则在总线上⼴播请求

### 两类总线事务
- **BusRd**：由读缺失触发，请求共享数据副本
- **BusRdX**：由写缺失或写升级触发，请求独占数据副本

### 缓存侦听机制
- 所有缓存控制器通过侦听总线信号来感知其他缓存的请求，并对总线请求做出响应
- 假设内存控制器对总线事务的响应晚于各缓存的 snooper，即优先由缓存响应总线请求，若⽆缓存响应则由内存处理

## 附录

### 1. Murphi 介绍

#### （1）Murphi 简介

Murphi 是⼀款显式状态协议验证器，由 Murphi 编译器和 Murphi 描述语⾔组成。

Murphi 编译器可根据 Murphi 描述⽣成专⽤验证器。该专⽤验证器能⽤于检查系统属性，包括错误断⾔、不变式和死锁情况。

Murphi 描述语⾔是⼀种⽤于有限状态异步并发系统的⾼级描述语⾔。其"⾼级"体现在，它包含了 Pascal 或 C 等常⻅⾼级编程语⾔的诸多特性。例如，Murphi ⽀持⽤⼾⾃定义数据类型、过程以及描述的参数化。

#### （2）Murphi 描述的结构

Murphi 描述包含常量、类型、全局变量和过程的声明，以及⼀组转换规则、初始状态描述和⼀套不变式。

Murphi 的⾏为部分由⼀组转换规则构成。每条转换规则都是⼀个带守卫的命令，包含⼀个条件（基于全局变量的布尔表达式）和⼀个动作（可修改变量值的语句）。

条件和动作均采⽤类 Pascal 语⾔编写。动作可以是包含循环和条件判断的任意复杂语句，但⽆论复杂程度如何，动作的执⾏都是原⼦性的——执⾏期间，其他任何规则都⽆法修改变量或对其造成其他⼲扰。

#### （3）Murphi 执⾏模型

Murphi 状态指为 Murphi 描述中的所有全局变量分配具体值的结果。

Murphi 描述的执⾏过程通过⽆限循环以下步骤⽣成：

**⽆限重复：**

a) 找出当前状态下所有条件为真的规则（即基于全局变量当前值，条件表达式结果为真的规则）

b) 任意选择其中⼀条规则并执⾏其动作，⽣成新状态

验证器⽣成状态的过程中，会检查各类条件。可能出现多种运⾏时错误，最典型的包括赋值操作或数组索引时的越界错误。动作中可调⽤显式的"assert（断⾔）"和"error（错误）"语句。若出现上述任意⼀种情况，验证器会停⽌运⾏，并输出诊断信息——包含从初始状态到错误状态的完整状态序列重构结果。若当前状态导致⽤⼾在描述中定义的某⼀不变式表达式为假，或当前状态为"死锁状态"（除⾃⾝外⽆后续状态），验证器也会执⾏上述操作。

### 常⻅问题

#### 1. Murphi 的解析器不⽀持 Windows 回⻋符（CRLF）

在使⽤ Murphi 编译模型⽂件时，如果出现如下错误提⽰：

```
msi.m:4 Bad input character
```

这可能是由于源⽂件使⽤了 Windows 格式的⾏尾符（CRLF）所致。

Murphi 的解析器仅⽀持 Unix/Linux 格式的⾏尾符（LF）。

可通过以下命令检查⽂件的编码格式：

```bash
file msi.m
```

若输出类似：

```
msi.m: Unicode text, UTF8 text, with CRLF line terminators
```

则说明当前⽂件使⽤的是 CRLF 换⾏符。请将其转换为 LF 格式。

**解决⽅法：**

**⽅法 1：使⽤命令⾏⼯具**

在 WSL、Git Bash 或 Linux/Mac 终端中执⾏：

```bash
dos2unix msi.m
```

若未安装，可通过以下⽅式安装：

```bash
sudo apt install dos2unix
```

**⽅法 2：在 VSCode 中修改**

1. 打开 `.m` ⽂件
2. 右下⻆状态栏中找到并点击"CRLF"字样
3. 在弹出的菜单中选择 LF
4. 保存⽂件（Ctrl + S）
