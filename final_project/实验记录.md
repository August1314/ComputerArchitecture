### 2025-12-02 CMake 调整与 OpenMP 兼容性处理

- **问题**：原 CMakeLists 在 arm64 平台强制使用 `-fopenmp`，AppleClang 默认不支持，导致 `image_benchmarks_optimized` 无法链接。
- **措施**：
  - 使用 `find_package(OpenMP)` 检测 OpenMP，可用时才链接 `OpenMP::OpenMP_CXX`。
  - 将优化可执行文件的编译选项改为仅包含 `-O0 -march=native`（x86 额外开启 `-mavx2 -mfma`），不强制 `-fopenmp`。
- **效果**：
  - 在当前 M4 Mac 上可以成功构建并运行 `image_benchmarks_optimized`，同时保留日后在支持 OpenMP 环境下开启多线程的可能性。

### 2025-12-02 高斯滤波优化（可分离卷积 + 循环展开）

- **原始实现**：直接按 3×3 核在二维上做双层循环，每个内点需要 9 次访存与多次加法，使用 `Image::at` 带来额外函数开销。
- **优化措施**：
  - 利用卷积核可分离性，将二维卷积分解为：先横向 1×3 卷积，再纵向 3×1 卷积。
  - 使用连续内存指针而非 `at()`，按行处理并对内部列做 4 路循环展开，减少索引计算与分支。
  - 中间结果缓存到 `std::vector<uint16_t>`，最终纵向卷积完成后统一右移 4 位完成除以 16。
  - 边界行列直接拷贝原图，避免复杂边界卷积逻辑。
- **correctness**：
  - `./image_benchmarks_optimized --benchmark_filter=GaussianFilter` 中正确性验证 PASS。
- **性能对比（Large 图像）**：
  - baseline：约 12.8 s
  - optimized：约 2.63 s
  - 加速比：约 **4.9×–5.0×**（不同运行略有波动）。

### 2025-12-02 Sobel 边缘检测优化（去 sqrt + 内存访问优化）

- **原始实现**：
  - 通过 `Image::at` 访问 3×3 邻域，分别计算 Gx/Gy，然后用 `std::sqrt(gx*gx + gy*gy)` 得到梯度幅值。
- **优化措施**：
  - 使用行指针获取邻域像素，避免频繁的索引函数调用。
  - 将梯度幅值从 \(\sqrt{G_x^2+G_y^2}\) 改为 \(|G_x| + |G_y|\) 的近似形式，并对结果在 0–255 之间饱和，省去 `sqrt` 和乘法。
- **correctness**：
  - benchmark 内置的正确性验证仍为 PASS，边缘形态与基准实现主观上保持一致。
- **性能对比（Large 图像）**：
  - baseline：约 11.98 s
  - optimized：约 1.91 s
  - 加速比：约 **6.0×–6.3×**。

### 2025-12-02 均值滤波优化（积分图）

- **原始实现**：
  - 对每个像素，遍历 kernel 区域内所有邻域像素求和，时间复杂度 O(WHK²)，在大图和较大 kernel 下非常慢。
- **优化措施**：
  - 构建尺寸为 `(height+1)×(width+1)` 的积分图 `integral`，存储前缀和。
  - 对每个输出像素，利用积分图在 O(1) 时间内获得任意矩形区域之和，根据有效窗口面积计算均值。
  - 通过坐标裁剪自然处理边界，保持与原逻辑一致的 padding 行为。
- **correctness**：
  - `image_benchmarks_optimized` 中 BoxFilter 的正确性验证 PASS。
- **性能对比（Large 图像）**：
  - baseline：约 31.3 s
  - optimized：约 4.29 s
  - 加速比：约 **7.0×–7.5×**。

### 2025-12-02 幂次变换优化（LUT 查找表）

- **原始实现**：
  - 对每个像素调用一次 `std::pow(normalized, gamma)`，在大图上反复计算幂函数导致显著的函数调用和浮点运算开销。
- **优化措施**：
  - 构建长度为 256 的 `unsigned char lut[256]`，事先根据传入的 `gamma` 预计算 `output = 255 * (i/255)^gamma`。
  - 主循环中仅做查表：`dst[i] = lut[src[i]]`，并用简单循环展开一次处理 4 个像素。
- **correctness**：
  - LUT 的计算公式与原实现完全一致，`image_benchmarks_optimized` 中 PowerLaw 的正确性验证 PASS。
- **性能对比（Large 图像）**：
  - baseline：约 6.78 s
  - optimized：约 0.161 s
  - 加速比：约 **40×+**。

### 2025-12-02 图像转置优化（缓存分块）

- **原始实现**：
  - 直接双重循环 `output(j,i) = input(i,j)`，访问模式在一个方向上跨行较多，容易触发缓存不友好的访问。
- **优化措施**：
  - 采用块大小为 32×32 的分块策略：外层按块遍历，块内按行连续访问输入并写出到输出中对应的小块区域。
  - 使用一维连续内存索引 `dst[j * height + i]`，减少 `at()` 带来的函数调用。
- **correctness**：
  - benchmark 中 Transpose 的正确性验证 PASS，随机尺寸图像（非 block 整除）下结果也与基准一致。
- **性能对比（Large 图像）**：
  - baseline：约 2.85 s
  - optimized：约 1.10 s
  - 加速比：约 **2.5×–2.7×**。

### 2025-12-02 图像旋转优化（缓存友好的块状旋转）

- **原始实现**：
  - 直接根据公式 `output(j, h-1-i) = input(i, j)` 进行双重循环，读写两侧都存在较多跨行访问。
- **优化措施**：
  - 与转置类似，使用 32×32 的块状遍历，将局部区域的旋转控制在同一缓存块内。
  - 统一使用一维索引 `dst[j * height + (height - 1 - i)]` 进行目标地址计算。
- **correctness**：
  - benchmark 内 Rotate90 的正确性验证 PASS，对若干宽高不同的测试图像（small/medium/large）旋转结果均与基准一致。
- **性能对比（Large 图像）**：
  - baseline：约 2.88 s
  - optimized：约 1.18 s
  - 加速比：约 **2.3×–2.5×**。
